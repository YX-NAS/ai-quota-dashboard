## F1 历史数据持久化

**动机**：当前每次快照从原始源重扫（默认回看 365 天，`AI_QUOTA_MAX_DAYS`）；各工具日志滚动清理后历史永久丢失。归档后历史可无限回看。

### 存储
- 新文件 `server/lib/history.js`；DB 路径 `path.join(plansStore.CONFIG_DIR, 'history.sqlite')`（天然继承 `AI_QUOTA_CONFIG_DIR` 隔离，测试可重定向）。
- `node:sqlite`，开 WAL、`busy_timeout=3000`。
- 表结构：

```sql
CREATE TABLE IF NOT EXISTS daily (
  date TEXT NOT NULL, tool TEXT NOT NULL,
  requests INTEGER, input_tokens INTEGER, output_tokens INTEGER,
  reasoning_tokens INTEGER, cache_read_tokens INTEGER, cache_creation_tokens INTEGER,
  cost_usd REAL, cost_cny REAL, equivalent_cny REAL,
  sub_usd REAL, pay_usd REAL, sub_requests INTEGER, pay_requests INTEGER,
  updated_at INTEGER,
  PRIMARY KEY (date, tool)
);
CREATE TABLE IF NOT EXISTS daily_model (
  date TEXT NOT NULL, tool TEXT NOT NULL, model TEXT NOT NULL,
  requests INTEGER, input_tokens INTEGER, output_tokens INTEGER,
  cache_read_tokens INTEGER, cache_creation_tokens INTEGER,
  cost_usd REAL, cost_cny REAL, equivalent_cny REAL, updated_at INTEGER,
  PRIMARY KEY (date, tool, model)
);
CREATE TABLE IF NOT EXISTS meta (key TEXT PRIMARY KEY, value TEXT);  -- schema_version 等
```

- **只存 per-tool 行，不存 `__total`**（合并时重算，避免双算）。

### 写入
- `index.js` 的 `buildSnapshot()` 聚合完成后，同步调用 `history.syncFromAgg(agg)`：把 `agg.daily` 全部日期的 per-tool 行与 per-model 行 UPSERT（`ON CONFLICT DO UPDATE`，单事务 + prepared statement）。幂等，约 2~4k 行/次，预期 <50ms。
- 优化留待优化阶段：内存记录上次写入内容指纹，仅脏日期落库。

### 读取与合并（关键口径：raw 优先、archive 只补缺）
- `history.mergeArchived(daily, models, pricer)` 纯函数：
  1. 读出 archived 的全部 (date, tool) 行与 (date, tool, model) 行；
  2. 对每个 (date, tool)：raw `daily` 中该日该工具**存在** → 原样保留（原始扫描为准）；**不存在** → 用 archived 行补入；
  3. `__total` 一律由合并后的 per-tool 行重算，禁止直接采信任何一边的 total；
  4. models 维度按真实结构 `agg.models[tool][model]` 补缺（注意：`models` 是 `tool -> model -> agg` 的全历史桶，无日期维度；补缺来源为 `daily_model` 归档行按 tool+model 聚合）；`dailyKeys` / `monthlyKeys` 重排。
- **归档成本重估（诚实口径）**：raw 行每次构建都按**当前**单价/汇率重算，归档行存的却是写入时点价——直接混编会污染趋势与环比。因此 merge 时对补缺的归档行按当前 pricer 重估：`daily_model` 有 token 明细，逐模型重算等价成本后汇总回 tool 行；`cost_usd`（实扣，Codex）与 `sub_usd/pay_usd` 不重估、保留归档原值；缺失模型单价时该模型金额置 0 并保留 token（与 raw 口径一致，页面本就标注「无单价」）。
- 合并发生在 `buildSnapshot` 内、返回前；`/api/summary` 与报表自动受益。
- `compareYesterday` 基于 raw rows，不动（昨日必在扫描窗口内）。
- `agg.monthly` 与 `agg.total` 维持 raw-only（当前无消费方），在 DESIGN.md 注明，避免日后误用。

### 边界
- 开关：`AI_QUOTA_HISTORY=0` 时完全不打开也不写库（纯内存路径回归 v1.4 行为）。
- DB 打开失败 / 写失败：记入 `collectorErrors.history`，主流程不受影响。
- `/api/summary` 的 days 上限 365 → 3650（归档可更久）。
- `.gitignore` 追加 `config/*.sqlite*`。

## F2 额度预警推送

**动机**：当前只有菜单栏/托盘本地通知，人不在电脑前收不到。

### 配置（plans.json 顶层新 key，TEMPLATE 同步补默认值）

```jsonc
"alerts": {
  "enabled": false,
  "webhookType": "ntfy",     // ntfy | bark | serverchan | generic
  "webhookUrl": "",          // ntfy: https://ntfy.sh/<topic>; bark: https://api.day.app/<key>;
                             // serverchan: https://sctapi.ftqq.com/<key>.send; generic: 任意 URL
  "thresholds": { "fiveHour": 85, "weekly": 85, "dailyGoalPct": 100 },
  "cooldownMinutes": 60
}
```

- **脱敏**：新函数 `maskWebhookUrl`（保留 `scheme://host/`，path+query 逐字符掩码为 `••••`）；`GET /api/plans` 对 `alerts.webhookUrl` 出掩码形态；`POST` 合并语义与 quotaKeys secrets 一致（提交值 === 掩码回显 → 保留原值；空串 → 清除）。实现并入 `plans.js` 的 `applyPlansUpdate` / `maskQuotaKeys` 附近。

### 引擎 `server/lib/alerts.js`
- `evaluate(snapshot, plans, now)` 纯函数 → firing 事件列表：
  - 三家 provider（`snapshot.chatgptQuota / zhipuQuota / minimaxQuota`，结构已核实为 `{available, provider, fiveHour:{usedPercent,resetAt?,resetMsLeft?}, weekly:{...}}`）× {5h, weekly}：`available && usedPercent >= threshold`；
  - 当日目标：今日 `__total` 等价成本 / `dailyGoal.cny >= thresholds.dailyGoalPct`（仅 goal>0 时启用）；
  - 事件冷却 key：额度窗口 = `provider|window|resetAt`（**P0 修订**：`resetAt` 缺失用 `fetchedAt + resetMsLeft` 兜底时，必须按 5 分钟桶量化 `Math.round(v / 300e3)` 再入 key——否则倒计时每次漂移几百毫秒，key 每轮不同，冷却永不命中，60s 重复推送；单测需模拟 ±2s 抖动断言 key 稳定）；无 resetAt 且无 resetMsLeft 的事件不发（无稳定冷却身份）。目标 = `goal|<北京时间日期>`。
  - 阈值读取逐字段兜底（老 plans.json 可能只有部分字段）：`thresholds.fiveHour ?? 85`、`weekly ?? 85`、`dailyGoalPct ?? 100`、`cooldownMinutes ?? 60`。
- 冷却存储：`history.sqlite` 加表 `alert_log(rule_key TEXT PRIMARY KEY, last_fired_at INTEGER, status TEXT)`（`AI_QUOTA_HISTORY=0` 时退化为进程内存 Map；重启冷却清零会重推一次，手册注明）。
- 发送 `send(adapter, title, message)`：仅允许 `http:`/`https:` 协议（显式拒绝 `file:`/`data:` 等），按协议选 `node:https`/`node:http`；不跟随重定向；10s 超时；fire-and-forget；结果写 alert_log（success/failed），**日志与 alert_log 只存失败原因，绝不存完整 webhookUrl（path 即密钥）**。失败不重试（下个评估周期受冷却约束自然再评估）。
- 适配器 payload（**P0 修订：ntfy 中文标题禁走 HTTP header**——Node 对非 latin1 header 值会同步抛 `ERR_INVALID_CHAR`，未捕获可崩服务）：
  - **ntfy**：从 webhookUrl 解析出 topic（path 去首尾斜杠，支持逗号分隔多 topic），POST 到**站点根**，JSON `{ topic, title, message, priority: 'default', tags: ['warning'] }`；
  - **bark**：POST `webhookUrl`（`https://api.day.app/<key>`），JSON `{ title, body, group: 'ai-quota' }`；
  - **serverchan**：POST `webhookUrl`，`application/x-www-form-urlencoded`，body 用 `new URLSearchParams({ title, desp })` 编码（title/desp 含中文与 Markdown，禁手拼）；
  - **generic**：POST `webhookUrl`，JSON `{ title, message, severity: 'warning'|'critical', source: 'ai-quota-dashboard', data: { percent, resetAt } }`。
- 文案（中文，只含百分比/金额/倒计时，**不含 token 明细**，控制推送泄露面）：
  - 「⚠️ 智谱 Coding Plan 5h 窗口已用 91%，约 47 分钟后重置」
  - 「💸 今日 AI 成本 ¥212 / 目标 ¥200（106%），已超支」
- 触发点：`index.js` `ensureFresh` 构建完成后**异步**调 `alerts.run(snapshot, plans)`；`run` 入口整体 try/catch（防 unhandledRejection），单条 send 抛错只影响自身事件，不影响其余发送与主流程；评估频率随快照 = 60s，足够。

### 边界
- `enabled=false` 或 `webhookUrl` 为空：引擎直接返回，不发请求。
- 单次评估最多发 7 条（3 provider × 2 窗口 + 当日目标，按冷却 key 去重后实发 ≤7）。
- 菜单栏/托盘行为不变（本期仅服务端推送）。

## F3 周/月报生成器

### `server/lib/report.js`
- `buildReport(agg, plans, opts, now)`，`opts = { type: 'week'|'month', offset: 0 }`（offset=0 本期，1 上一期…）。
- 周期口径：周 = 北京时间 ISO 周（周一 0 点起，沿用 mcp.js 的周起算逻辑，抽成 `store.js` 导出 `weekStart(now)`）；月 = 北京自然月。
- 输出 `{ title, markdown, data }`，Markdown 章节：
  1. 标题（周期起止日期 + 生成时间）
  2. 总览：本期总成本（等价口径脚注）、请求次数、token 总量，环比上期 ↑↓%
  3. 工具榜：每工具 请求 / 成本 / 环比
  4. 模型榜 Top5：请求 / 成本
  5. 最贵的一天 + 金额
  6. 预算达成率（配置了 `dailyGoal` 或对应工具 `cnyPerMonth` 才出）
  7. 口径脚注（订阅制=等价成本非实扣；数据来自本机原始日志扫描 + 本地归档）
- 上期对比数据不足（无记录）时显示「上期无数据」，不显示百分比。

### API
- `GET /api/report?type=week|month&offset=N` → `{ ok, title, markdown, data }`；参数校验（type 白名单；offset 上限按类型区分：week 0~520、month 0~120）。

### 网页（web/app.js + index.html + style.css）
- 新增「周报 · 月报」区块：位置在工具卡区之后、每日明细之前。
- 交互：周/月 tab、上一期/下一期切换、Markdown 预览（极简渲染：标题/加粗/列表/表格，其余 `<pre>`）、「复制 Markdown」按钮（navigator.clipboard + 降级 execCommand）、「下载 .md」。
- 视觉沿用现有暗夜玻璃卡片风格；空数据出占位文案。
- 周起算：前端 `web/app.js:221` 已有独立实现，抽公共逻辑收益小——前端保持现状并在两处注释互指，避免口径分叉（本期不在前端大改）。

### MCP
- `mcp/mcp.js`：`TOOLS_DEF` 加 `ai_usage_report`（参数 `type: week|month`、`offset`），文本输出 markdown；CLI 加 `node mcp.js report week [offsetN]`。

## 风险与对策
| 风险 | 对策 |
|---|---|
| archive 与 raw 双算 | 「raw 优先、archive 只补缺、total 永远重算」+ 专项单测（部分删除场景） |
| /api/summary payload 变大 | days 上限仍由参数控制，前端默认 30/90 不变；观察后优化 |
| webhook 泄露敏感信息 | 默认关闭；消息只含百分比/金额/倒计时；URL 掩码回显；alert_log 不存 URL |
| 每 60s 全量 UPSERT 开销 | 单事务 + prepared；优化阶段加脏日期指纹跳过 |
| 历史库损坏拖垮主服务 | 打开/写失败一律降级记 error，不阻塞快照 |
| 云同步盘 WAL 撕裂（本项目 config 常驻网盘/同步盘） | WAL 初始化失败降级 `journal_mode=DELETE`；手册 FAQ 建议把 AI_QUOTA_CONFIG_DIR 指到本地盘 |
