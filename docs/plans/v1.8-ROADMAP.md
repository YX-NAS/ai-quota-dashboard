# v1.8 优先级路线图（PM 视角：功能 · 交互 · 算法审计后）

> 状态：**已交付**（v1.8.0，2026-11-11，commit 0ab530c）；文末「未做」清单为下一期输入
> 范围基线：v1.7.4（main @ d2fa6b6）
> 审计方式：以项目经理身份通读采集层 → 聚合层 → API → 前端，对照真实运行数据（本机 7788 + 云端只读端）找「用户会踩到但不报错」的问题

## 0. 判断依据

这个项目已经过了「能不能跑」的阶段：6 个采集器、5 个推送通道、云端只读部署、218 个测试都在。真正剩下的风险不是功能缺失，而是**口径与可信度**——数字算错不会报错，用户看不出。所以本期只做四件事，全部围绕「让结论可信、让异常可见」。

## 1. 本期做（P0 → P1）

| 优先级 | 事项 | 为什么是它 | 落点 |
|---|---|---|---|
| **P0-A** | 月度预估口径修正 | 分母用「有数据的天数」：跳过的周末不进分母 → 日均虚高 → 月底预估系统性偏高；新装首日半天除以整天 → 预估只有真值一半。**同一概念在前后端各写一遍**，还带一个 `tools.__total` 回退 bug | 新增 `server/lib/forecast.js`（唯一实现）；`store.monthlyForecast` 委托它；前端只读 `snap.forecast` |
| **P0-B** | 快照补采集状态与预估 | 没有行数/耗时/归档状态，出错只能翻日志；前端各自做除法是口径漂移的温床 | `collectorStatus` / `historyStatus` / `forecast` 三个字段 |
| **P1-A** | 今日速览 | 10 个区块 + 6 张卡，「今天什么情况」要用户自己算；首屏没有结论就等于没有看板 | `web/js/summary.js` → `#todaySummary` |
| **P1-B** | 数据健康面板 | 错误埋在 6 张卡底部的 `.fresh` 小字里；用户看到怪数字第一反应是「这软件不准」 | `web/js/health.js` → `#healthSec`，有错自动展开 |
| **P1-C** | 移动端适配 | 云端看板主要入口是手机；此前只有 1080px 表头冻结与 640px 文案换行，工具卡在手机上挤成两列窄条，日报宽表把整页撑出横向滚动 | `style.css` 640px 断点 + `.report-md{overflow-x:auto}` |
| **P2** | 只读端不误报 | 云端没有 `~/.zcode` 等源，六采集器必然打不开库；照实上报会让健康面板天天「2 个数据源异常」并自动展开，真故障淹没在假告警里 | `snapshot.js`：readonly 下不返回本机采集器状态，健康面板改显「数据来自主端同步」 |

**明确不做（本期）**：Web i18n、版本更新检查、macOS 签名公证。三者都不是「算错/看不见」类问题，且各自需要独立决策（翻译谁来维护、更新检查要不要联网、签名要不要 Apple 账号年费），不塞进一个口径修复版本。

## 2. 验收标准

- 预估口径：`monthForecast` 单测覆盖「跳周末」「月中新装」「不足 6 小时」「工具无数据不回退 `__total`」「当日外推」「日界」6 条；快照断言「各工具已花之和 ≤ 本月合计」。
- 可信度：任意采集器失败时，健康面板对应行变红并带原始错误；正常时默认收起不占屏；重渲染保留用户的展开状态。
- 移动端：390px 下 `documentElement.scrollWidth === 390`（此前 438）；工具卡单列、KPI 两列。
- 一致性：本机与云端同一份代码；云端 `readonly:true`、`collectorStatus:{}`、无本机采集器错误。
- 回归：`npm test` **225 passed, 0 failed**。

## 3. 未做 / 下一期候选（按「用户可感知的损失」排序）

1. **截图全面过期（P1，低成本高感知）**：`docs/screenshots/*.png` 停在 v1.5，README 首屏图还是旧配色与 5 张卡。需要带假凭据 + dsh 演示数据的截图环境（`scripts/gen-demo-data.js` 目前不生成 dsh、不写 plans.json），且真实数据含成本/VPN/SSID 不能公开——**这是唯一的「门面」欠账**。
2. **Web i18n（P2）**：README.en 已说明欢迎 PR；真做需要一套 UI 文案抽取 + 语言切换持久化，工作量中等、收益看用户群。
3. **版本更新检查（P2）**：轮询 GitHub Releases + 页脚提示。需要决定是否向 GitHub 发请求（隐私说明要跟着改），以及在 Clash/fake-IP 环境下的超时降级。
4. **macOS 签名公证（P3）**：`menubar/AIQuota.app` 目前未签名，首次打开要右键「打开」。需要 Apple 开发者账号（$99/年），属于账号决策而非代码决策。
5. **Windows 托盘/桌面卡片真机回归（P3）**：代码已在，处于「社区验证阶段」，缺真机回归清单。
6. **性能/健康度看板（P3）**：v1.5 计划里的「错误/重试健康度卡片」「响应性能看板」仍未做；当前健康面板已覆盖「数据侧」，缺「服务侧」（API 延迟、快照构建耗时的历史趋势——`collectorStatus.ms` 已经在数据结构里，沉淀即得）。

## 4. 经验（留给下一个接手的人）

- **两处实现必然漂移**：`monthlyForecast` 当年被标成「仅测试/预留」，但它和前端那份实现注定对不上。规则：一个口径一个实现，另一处只能消费。
- **沉默的错误最贵**：采集器失败会降级成空数据，页面照样好看。凡是「降级后看起来正常」的路径，都要有可见的出口。
- **展示端与采集端的职责边界**：云端没装的工具不该报错。跨角色的错误要按角色过滤，否则告警会训练用户忽略告警。
